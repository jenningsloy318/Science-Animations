## Options Considered

### AC-06 physics numbers: use the rounded textbook mass set (2.014102/3.016049/4.002602/1.008665 u → 0.018884 u) rather than full-precision AME2020 values

NIST/AME2020 full-precision masses (D=2.01410178, T=3.01604928, ⁴He=4.00260325, n=1.00866492) yield 0.018883 u, which breaks the exact on-page arithmetic 2.014102+3.016049−4.002602−1.008665 = 0.018884 and the deterministic literal '0.0189' required by SCENARIO-015. The rounded textbook set reproduces the whole consistent chain — 0.018884 u × 931.494 MeV/u ≈ 17.59 ≈ 17.6 MeV (Wikipedia primary source confirms 17.6 MeV with 14.1 MeV/80% to the neutron, ~3.5 MeV to the alpha; HyperPhysics independently confirms 17.59 MeV with 79.87% to the neutron), and 17.6 MeV × 1.602e-13 J/MeV ≈ 2.82e-12 J (SCENARIO-016). Recommendation: display the AC-06 numbers verbatim as written; they are physically correct AND internally consistent, with the forbidden literals 0.0256/3.2e-11 absent.
### AC-07/SCENARIO-017 pause-resume: custom simTime accumulator gated by a paused flag, NOT THREE.Clock.running toggling

Toggling THREE.Clock.running is a documented trap (three.js forum): getDelta() returns a huge jump after resume because oldTime is stale during the pause, and clock.start() resets elapsedTime to 0 — either breaks 'resume continues exactly from the frozen phase'. The robust pattern: keep calling clock.getDelta() EVERY frame (keeps oldTime fresh) but only accumulate when unpaused (if (!paused) { simTime += dt; updateParticles(dt); advancePhaseMachine(simTime); }). This freezes particle motion AND the phase clock simultaneously, resumes with no jump, and makes the 🔄 重置 button simply reset simTime/phase to 等离子体 (AC-08) without touching tour state. Alternative (own Date.now() deltas) works but duplicates Clock; the r167+ Timer class does not exist in r160.
### AC-09/SCENARIO-022 zero-console-warnings in r160: rely on modern r152+/r155 defaults — never set useLegacyLights, outputEncoding, or texture.encoding

Since r152, WebGLRenderer.outputColorSpace defaults to SRGBColorSpace and ColorManagement.enabled defaults to true (three.js forum announcement); since r155, useLegacyLights is deprecated (default false) and setting it logs a deprecation console warning — it was removed in r165 (three.js Migration Guide). Legacy non-module builds were deprecated at r160, so the import-map ESM approach of AC-03 is also the warning-free path. Recommendation: zero legacy property writes, physically-correct light intensities (no light-intensity rescaling needed since this scene is emissive/unlit particles), set texture.colorSpace = SRGBColorSpace only for color textures (e.g., canvas-generated glow textures); this satisfies both the zero-warnings check and the r160 pin.
### SCENARIO-024 WebGL degradation: import WebGL from 'three/addons/capabilities/WebGL.js' (r160), test isWebGL2Available(), but render a custom Chinese message div

In r160 the module exports a default class WebGL with static isWebGL2Available()/getWebGL2ErrorMessage(); three.js only supports WebGL 2 in modern versions (three.js forum). The built-in getWebGL2ErrorMessage() returns an ENGLISH message ('Your graphics card does not seem to support WebGL 2'), which would fail the Chinese-explanation requirement — so use isWebGL2Available() for detection and inject our own Chinese DOM message instead of appendChild(WebGL.getWebGL2ErrorMessage()). Alternative try/catch around new WebGLRenderer() is riskier (three logs console errors during renderer construction, violating 'no unhandled console error in the degradation path').
### AC-04 + NFR performance: single THREE.Points with BufferGeometry (typed-array position updates) for the ≤2,000 plasma particles + a few Mesh nuclei + AdditiveBlending Sprite flash; dispose on phase rebuild

THREE.Points renders all plasma electrons/nuclei-bodies in one draw call with per-frame typed-array writes (Stack Overflow/discourse best practice for thousands of particles) — individual Mesh spheres at 2,000 particles would mean ~2,000 draw calls and miss the 60 fps target. The energy flash should be a SpriteMaterial {blending: AdditiveBlending, transparent: true, depthWrite: false} whose scale/opacity animate then fade (ICS MEDIA glow technique; depthWrite:false avoids transparency-sorting artifacts). Phase rebuilds must call geometry.dispose()/material.dispose() per the official how-to-dispose-of-objects manual (GPU resources are not GC-managed; renderer.info.memory verifies leaks) — this directly serves the NFR 'geometries/materials disposed on phase rebuild' and the AC-08 auto-repeat loop that rebuilds the plasma phase indefinitely. Keep the import map exactly per the official Installation manual (three → jsdelivr three@0.160.0/build/three.module.js, three/addons/ → examples/jsm/), which also carries the manual's warning to keep every dependency on the same version+CDN — grounding AC-03's 'exclusively one pinned version' clause.
