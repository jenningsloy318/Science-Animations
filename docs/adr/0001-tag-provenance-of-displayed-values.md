# 对外展示的科学数值一律携带来源标签

本仓库把**认证纪录、实测值、导出值、示意值**四类数字混排在同一批动画里且无区分，导致读者与后续审计者都无从判断一个数字的分量。决定：**每一个对外展示的科学数值**都必须携带机器可读的来源标签（`certified` / `measured` / `derived` / `illustrative`）。

## 背景

这是审计中 `ion-thruster-3d` 预设暴露出的真实病灶：NEXT 那组数据同时展示了实测的推力、功率与质量流，以及一个与同组 `Isp` 互相矛盾的导出排速。任何只盯着单一数字的修补都无法解决它——因为问题不在数字，在于**读者无法分辨哪些数字可以互相印证、哪些必须独立看待**。

同一病灶的另一个表现是字段语义过载：`propellant_kg` 这一名字没有回答「是航天器装载量、全程消耗量，还是地面寿命试验通过量」，于是同一个字段在不同条目下悄悄承载了三种含义。

## 考虑过的选项

| 方案 | 为何未采纳 |
|---|---|
| **只给被审计点名的数值加标签** | 成本低，但未点名的混排陷阱原样留给下一个审计者——病灶恰恰在于「没人知道哪里还有」。 |
| **只改错数字，不引入标签** | 最便宜，但切割准则将永远依赖主观判断，且字段语义过载这类病无药可医。 |
| **全量来源标签**（采纳） | 成本最高，但它是**唯一**能让「这个数算不算真值」变成可机检问题的方案。 |

## 后果

- 每一个对外数值都要有一行来源注释，是持续的书写负担；换来的是切割准则与保鲜门禁有了可执行的支点。
- 未标注者从严按「导出值」处理，因此遗漏会立刻暴露，而不是静默通过。
- 标签一旦成为门禁的依据，审计与测试都会依赖它；反向调整的代价随之升高。
