# docs/requirements 下的规格是活文档，不是历史快照

本仓库的规格文档描述的是站点**现在**应该是什么样。决定：科学事实演进时，`docs/requirements/` 下的规格**随之更新**，而不是冻结在撰写当时的数值上。

## 背景

规格天然被当作历史快照阅读——「当时就是这么定的」。审计发现隆基单结硅纪录刷新时，一个世界纪录数字已经同时出现在当前代码、根门户卡片、以及两份规格文档里，其中一份还是该项目的**权威需求文档**（含物理极限对照表）。

若把规格当快照，就必须引入「已被取代」标记体系；而读者仍会先读到旧值，再去别处找新值——对一个给孩子看的站点，这个顺序本身就是错的。更糟的是「俄歇 29.43% > 隆基 27.81% > 量产 24.5%」这样的对照关系一旦在权威文档里失效，它会以最不容置疑的姿态继续被引用。

## 考虑过的选项

| 方案 | 为何未采纳 |
|---|---|
| **规格一律不动** | 会在代码与权威需求文档之间留下永久矛盾的数字，且矛盾方占据「最不容置疑」的位置。 |
| **规格冻结 + 加「已被取代」标记** | 保留历史真实性，但读者先读到旧值；对「让孩子读到当前真相」这一首要目标来说是次优解。 |
| **活文档，一并更新**（采纳） | 牺牲了「规格记录当时状态」这一性质。换来规格与代码始终描述同一个现在。 |

## 后果

- 无法从规格推断「这份需求是何时写的」，故每份活文档需自行标注**需求快照日期**。
- 数值更新时必须跨文档同步，这是额外工作量；换来的是全库不存在互相矛盾的科学数字。
- 评审类文档（如 `REVIEW.md`）不属于活文档——它们记录的是一次具体评审，保持原样并加指向当前规格的注记即可。
